# Lightning Azent P13 — optional HAE consumer bridge (2026-11-10 KST)

## Goal and decision
The customer product remains HAE, but its current GUI/HTTP paths use legacy `axflow`.
Implement a strictly optional HAE planner -> LA runtime boundary in the private
`feature/lightning-azent` branch. Preserve existing HAE routes, data, plans,
SQLite ledgers, production and unrelated branches. No external services.

Two designs were compared: (A) direct change of `web.py` / engine cutover
(higher migration risk, requires full Windows and browser regression, no direct
cost), and (B) version-pinned opt-in adapter with an injected executor (selected:
no new dependency, low regression risk, but no customer GUI cutover).

## Implemented
- `packages/lightning-azent/lightning_azent/hae_bridge.py`: fail-closed
  `azent.api.v0` / metadata-only audit / synthetic-only handshake; bounded IR
  review without SQLite initialization; plan + run + source-version + write-step
  request digest; explicit owner confirmation flag and exact digest for synthetic
  SQLite writes; manual execute/resume and read-only receipt/status/audit facade.
- `apps/ax-flow/axflow/la_adapter.py`: opt-in `HAEConsumer` binds the existing
  deterministic HAE `plan_request` to the LA bridge for preview, execute and
  evidence. This is importable by HAE consumers; original web routes do not
  use it yet.
- `tests/test_hae_bridge.py` (14 cases) and
  `apps/ax-flow/tests/test_la_adapter.py` (7 cases).

## Security and acceptance
- The request digest is **not a cryptographically authenticated user approval**.
  HAE is responsible for authenticating the real owner and storing scoped
  confirmation. Never auto-approve; programmatic caller can forge the boolean.
- No customer data, OAuth, provider connector, SOVIA independent audit,
  DBVORA live restore, paid CI, network/API call or production deploy.
- This limited bridge does not make local external actions exactly-once.
- **Estimated final-product progress: 60% -> 68% provisional (+8pp)** for new
  optional integration and consent/evidence boundaries. **70% target NOT
  verified**; external services, actual HAE GUI cutover and customer package
  remain HOLD.
