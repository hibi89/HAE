# REA_AI — Lightning Azent 기반 로컬 추론·탐색 연구 가설

> OWNER RESEARCH IDEA / 2026-10-29 KST · **미개발 / 미검증 / 장기 연구 백로그**.
> 사용자와 해총의 탐색적 대화를 공식 연구 아이디어로 보관한다. 이것은 기술적 실현 가능성이나 AGI/ASI 수준 성능을 입증한 문서가 아니며, 즉시 구현·새 저장소 생성·기존 제품 범위 변경 승인이 아니다.

## 1. 연구 동기

대규모 클라우드 AI가 수행하는 계산 중 일부를, 작고 저렴한 로컬 모델 + 명시적인 알고리즘 + 문제별 검증 + 병렬 탐색 + 결과 피드백으로 대체해 **동일한 문제 해결 성능에 필요한 실제 연산 비용**을 낮출 수 있는가?

사용자의 장기 비전은 네트워크나 타 컴퓨터 의존성을 낮추고, 한 대의 개인 컴퓨터에서 폭넓은 문제를 다루는 로컬 AI 시스템을 만드는 것. **AGI 이상 구현은 가능성 미확인 장기 가설**이며 현재의 성공 기준이 아니다.

## 2. 제안한 핵심 기술 가설

1. **문제 외곽 경계 구성:** 무료/오픈웨이트 로컬 Qwen 계열 등 작은 언어모델을 우선 후보로 검토해 자연어 문제의 목표, 변수, 제약조건, 미확인 가정을 구조화한다. 모델의 제약 제안은 **검증되지 않은 가설**이며, 모델 하나의 판단만으로 정답 후보를 영구 제거하지 않는다.
2. **검증 가능한 문제 표현:** 형식 스키마, 수학적 제약, 정책, 타입·범위를 검증하고 불명확한 조건을 구별한다. 자명한 불가능 영역만 증거 기반 제거; 불확실한 영역은 남겨둔다.
3. **계층적 섹터 분할:** 탐색 공간을 추적 가능한 식별자와 중첩/포함 관계를 가진 섹터로 나누고, 우선순위 및 예산에 따라 동적으로 세분화/병합한다.
4. **ML 탐색 정책:** 초기에는 트리 기반 순위 모델 및 Contextual Bandit 등 작은 ML로 섹터의 예상 효용·불확실성·비용을 고려해 작업자와 자원을 배분한다. 필요할 때만 장기 보상 RL·GNN 등 후보 검토.
5. **로컬 병렬 실행:** 여러 작업자가 탐색을 수행하되 중복·재시도·중간 결과를 기록한다. 단순 병렬화는 계산량 절감을 의미하지 않으므로 실제 CPU/GPU/RAM·벽시계 시간·총연산량을 분리해 측정한다.
6. **문제별 검증과 피드백:** 수학·제약문제에는 유효성/경계 증명, 코드에는 실제 테스트·반례 등 신뢰할 수 있는 피드백을 사용한다. 실행 중 후보 수정과, 장기적인 정책 학습/검증된 스킬 저장을 구분한다.
7. **경계 재검토:** 실패 원인이 LLM의 문제 구조화인지, 탐색 정책인지, 검증기의 불확실성인지 분리 추적한다. 정답에 가까운 듯 보이는 점수는 실제 정답 보증이 아니다.

### 중요한 반증 조건

- **균등 무작위 비밀/암호**는 성공 위치의 통계적 단서가 없다면 ML이 일반적으로 탐색량을 줄일 정보를 얻지 못한다. 해싱·세분화·병렬 실행만으로 정보 이론적 난제를 해결하지 못한다. 암호 예시는 개념 설명일 뿐 실서비스 암호 공격 연구가 아니다.
- 범용 토큰 추론은 단순 전수 대입과 다르다. LLM의 큰 연산 비용은 주로 대형 신경망의 반복된 행렬 연산에서 나온다. 따라서 이 연구는 모든 LLM 추론을 탐색 문제로 단순화하지 않는다.
- 검사 가능한 일부 분야에서 대형 모델 대비 효율적일 수 있어도 **범용 AGI/ASI 달성이나 전 분야 우월성 주장 금지**.

## 3. 선행 조건 — LA 먼저 완성·검증

**사용자 결정: n8n과 유사한 시각화/플로우 실행 기반이 필요하므로 Lightning Azent(LA) 플로우 엔진을 먼저 개발·테스트하고, REA_AI는 그 이후 실험한다.**

- 기존 독립 LA 패키지 및 HAE↔LA 합성 실행의 검증된 기능은 출발점이지, 범용 분기·상태·자원 할당·작업자 관리 기능이 모두 완성됐다는 뜻이 아니다.
- REA_AI에 필요한 LA 확장 후보: 선언형 단계 IR, 병렬 작업 분기/합류, 예산·시간 한도, 재시작/재시도/중복 방지, 중간 증거·실행 영수증, 실행 취소 및 상태 조회. **현재 각 기능의 실제 지원 여부를 확인한 뒤 부족한 것만 개발**한다.
- LA 실행 기능과 REA_AI 연구는 분리한다. 이 가설로 HAE 판매용 MVP, KIC·PayPal·UGREEN 공식 제출 범위를 늘리거나 현재 개발 브랜치에 실험 코드를 무단 추가하지 않는다.
- 의존 흐름: **LA 유효한 실행 계약/테스트 → 오프라인 검증 가능한 문제의 실행 플로우 → 작은 로컬 LLM·ML 실험 → 결과 비교 → 확대 여부 판단**.

## 4. 최소 실험 설계 (지금은 계획만)

| 단계 | 실험 | 통과를 판단하는 근거 |
|---|---|---|
| E0 — 실행 기반 | LA로 독립적인 로컬 작업 분할·중복 방지·실행 기록 테스트 | Windows에서 재현 가능한 작업/실패/재시작 테스트 |
| E1 — 첫 문제 | 정답·제약을 검증할 수 있는 **합성 조합 최적화 또는 제약 충족 문제** | 전수/결정론적 탐색 기준선과 동일한 정답성 |
| E2 — 정책 비교 | 일반 탐색 vs 고정 섹터 병렬 vs ML 유도 동적 분할/병렬 | 동일 예산의 정답률·처리 시간·실제 탐색 횟수·RAM/CPU/GPU 비교 |
| E3 — 피드백 | 부분 검증 신호 사용, 후보 수정, 기록 재사용 | 홀드아웃/미지 문제에서도 측정 가능한 개선; 학습 데이터 누수 방지 |
| E4 — 범위 확장 | 코드 테스트 등 별도 검증기 기반 두 번째 문제 영역 | 단일 도메인 과적합이 아닌지 점검 |

초기에는 유료 API·GPU 학습·고객 정보·외부 모델 대량 수집을 쓰지 않는다. 오픈웨이트 모델과 공개 라이선스를 확인하고, 특히 **비공개 상용 모델의 출력 수집·증류/대체 모델 학습은 약관·권리 검토 없이 수행하지 않는다**.

## 5. 종료 조건과 의사결정

- 동일한 검증 정확도에서 연산량·자원·시간이 개선되면 특정 과제의 유효한 기술 실험으로 인정하고 다음 문제 영역으로 확장한다.
- 단순 병렬화만으로 벽시계 시간이 줄거나 일반화가 없으면 범용 지능 향상으로 주장하지 않는다.
- 검증 신호가 없는 문제, 병렬 오버헤드, 잘못된 경계 축소, 피드백 보상 왜곡 등 부정적 결과도 기록하고 탐색 전략을 재설계한다.
- 사용자 재승인 이전에는 **연구 아이디어의 보존만 수행**한다. 별도 REA_AI 저장소·제품 코드·새 작업 슬롯을 자동 생성하지 않는다.

## 6. 해총 인수인계

해총 PUBLIC 상황실에는 **REA_AI 장기 연구 가설 존재, LA 검증이 선행, 아직 미착수라는 사실과 본 PRIVATE 문서 링크만** 보관한다. 내부 기술 연구 상세와 고객·비공개 자료를 공개 저장소에 복제하지 않는다.
