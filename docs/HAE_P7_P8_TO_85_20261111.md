## Risks and design choice

Alternative A: store customer business assets and workflow definitions in existing HAE runtime ledger; simpler single DB but lifecycle/retention and disaster recovery linked, rollback complexity high. Alternative B (selected): independent SQLite metadata catalog and immutable registry, each owner-initialized, no silent migrations, no source DB mutation except approved synthetic work. All real external provider actions prohibited pending approval.

Source identity protection: registry refuses overwriting an older asset SHA and source drift, checks protocol against selected loopback synthetic SQLite, stores **no absolute source path, SQL statements or business rows**, returns public fingerprint/counts only. Workflow catalog DOES persist *owner-approved task text and relative CSV filename*, alongside SHA256 of CSV and typed IR; listing only shows ID+workflow and reload requires unchanged original. UI uses Origin/Host checking, manual checkbox, duplicate submit guard, stale token invalidation.
